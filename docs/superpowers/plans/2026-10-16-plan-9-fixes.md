# Folk Dance Player — Plan 9: Fixes from the 0.1.0 Hardware Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what the 0.1.0 hardware check found, and add the small requests queued for 0.2.0:
- **Esc** closes the projector view over the laptop on the first press.
- **Canva's controls never show** on the live slide, and a slide change never flashes the previous slide.
- **A long dance name** no longer hides the player bar's countdown.
- **The deck-link hint** names Canva's real menu path: Share → Embed → Smart embed link.
- **"Generating preview…"** shows with a moving bar while a linked slide's image is saved. Offline, a message says it will be made once the connection is back, and it is.
- **"Edit details"** in a song's menu (program items, Holding, the library list) opens the song in the Music page's editor. Holding and library rows get a "⋯" / right-click menu.
- **The release PR's PR Gate** starts with GitHub's "Approve workflows to run", and no longer runs twice.

**Architecture:** Each fix stays in the module that owns the behaviour:
- **`ActivityWatcher`:** the grace after opening applies to the mouse only.
- **`LiveSlide` / `createLiveView`:** a `LiveView` is covered (`cover(imageUrl)`), revealed (`reveal()`) or hidden (`hide()`). A second view on top shows the saved image while the Canva page, still visible underneath, loads and fades its controls.
- **`CanvaService`:** skips captures while offline and gains `catchUp()`. A `ConnectionWatcher` in main calls it when `net.isOnline()` turns true.
- **The renderer:**
  - `useOnline()` (the dance editor's slide field)
  - `EditSongProvider` / `useEditSong()` (App) over a new library-store action, `reveal(songId)`
  - a shared `<SongMenu>` and `openRowMenu`
- **The PR Gate** drops the `ready_for_review` trigger.

**Tech Stack:** As Plans 1–8. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-13-folk-dance-player-electron-design.md`. Read §6.2 (program list, holding panel), §6.3 (the slide field), §7.3 and §8.1 (laptop mode), §8.3 (Canva), §10.2 and §13.2–13.4 (the release flow). This plan updates those sections as it goes. **Found while planning:**
- **Esc (A.2 in the checklist):** confirmed with the user. Pressed two or more seconds after turning the view on, one Esc works; sooner, it doesn't. `ActivityWatcher.closeLaptop` ignored Esc for 1 s after opening, the same grace that stops the click on the switch from closing the view by moving the mouse. With auto-show, the view had been up for a while, so one Esc always worked (A.3).
- **Canva (C.8, C.9):** a spike loaded the user's own deck, "Master Harrisburg Folk Dance Catalog", in a `WebContentsView` the way `LiveSlide` does, and captured the view at the reveal. The page of a view hidden with `setVisible(false)` has `document.visibilityState` set to `hidden`, so Chromium throttles it:
  - **Controls:** Canva's controls were fully visible 150 ms after the reveal, and faded only once the view was visible (C.8).
  - **Slide change:** after `#2` loaded while hidden, the reveal still showed slide 1 (C.9).

  Three alternatives were tried:
  - **`backgroundThrottling: false`:** fixed the slide change, but the page still reported `hidden` and a faint ghost of the controls remained.
  - **Parking the view outside the window:** still hidden, and both bugs came back.
  - **A second view on top as a cover:** kept the page `visible`. It showed no controls at the reveal and the right slide, and is this plan's fix. A `data:` cover page loading `fdp-media://slide/…` in the default session was checked off-screen.
- **Release PR:** GitHub now creates the PR Gate run of a pull request opened with a workflow's token but holds it for approval (GitHub Docs, "Triggering a workflow"; seen since mid-2026). The user clicked **Approve workflows to run** on the 0.1.0 release PR (#21), which ran the gate. Then **Ready for review** started a second run (`ready_for_review`), which was cancelled ("a higher priority waiting request … exists") and left the PR blocked until a re-run.
- **Offline linking:** linking a slide offline made its capture fail at once ("Couldn't save the slide image"), and nothing retried until a restart or Refresh slides.

**Decisions made with the user while planning:**
- **The library-row menu** has **Edit details** and **Add to / Remove from favorites** (not a full song menu).
- **Song menus** open from a "⋯" on hover, or a right-click on the row. Program items already did; library and Holding rows now do too. The Music page's table gets the same menu: there, Edit details just selects the song.
- **Offline,** the slide field shows a message instead of the bar: "The slide preview will be generated when you're back online."
- **The release PR stays a draft** (the pause for the hardware checklist). The gate starts with "Approve workflows to run", not Ready for review.

import { slideBox, type Rect } from '@shared/projector'

// The Canva page shown over the projector's slide area: a WebContentsView in Electron, with a
// cover over it. A hidden page is throttled by Chromium: Canva never fades its controls and the
// page keeps its last picture, so the page stays visible under the cover while it gets ready.
export interface LiveView {
  load(url: string): Promise<void> // resolves once the page has loaded
  nudge(): void // a synthetic mouse pass, so Canva starts fading its controls
  cover(imageUrl: string | null): void // the saved image (or black) over the page
  reveal(): void // the cover goes: the live page shows
  hide(): void // neither shows
  setBounds(bounds: Rect): void
  destroy(): void
}

export interface LiveTarget {
  deckId: number
  viewUrl: string
  pageId: string
  position: number
  imageUrl: string | null // the saved image, which covers the page until it is ready
}

// Canva fades its controls about 10 s after the last mouse activity; a slide change within a
// loaded deck needs only a moment to draw.
const FADE_MS = 11_000
const HASH_FADE_MS = 1_500

// Spec §8.3, "saved image, then live": the projector page shows the saved image at once, and the
// live view stays covered by the same image until its controls have faded, then is revealed over
// the image exactly. Offline, or when the page fails to load, it never shows. `onChange` fires when
// the live view appears or goes.
export class LiveSlide {
  private view: LiveView | null = null
  // The deck the view has loaded with its controls faded. Until the fade, a switch starts over:
  // another slide's load would skip the nudge, and the controls would stay up.
  private deckUrl: string | null = null
  private target: LiveTarget | null = null
  private live = false
  private generation = 0
  private timer: ReturnType<typeof setTimeout> | null = null

  constructor(
    private readonly deps: {
      createView: () => LiveView
      online: () => boolean
      size: () => { width: number; height: number } | null // the projector window's content
      onChange: () => void
    }
  ) {}

  show(target: LiveTarget | null): void {
    if (target && this.target && same(target, this.target)) {
      // The image was saved (or saved again) while the page loads: it becomes the cover.
      if (!this.live && target.imageUrl !== this.target.imageUrl) this.view?.cover(target.imageUrl)
      this.target = target
      return
    }
    const wasLive = this.live
    this.cancel()
    this.target = target
    if (!target || !this.deps.online()) {
      this.view?.hide()
      if (wasLive) this.deps.onChange()
      return
    }
    const sameDeck = this.view !== null && this.deckUrl === target.viewUrl
    if (!this.view) {
      this.view = this.deps.createView()
      this.resize()
    }
    const view = this.view
    view.cover(target.imageUrl)
    if (wasLive) this.deps.onChange()
    if (!sameDeck) this.deckUrl = null
    const generation = this.generation
    view.load(`${target.viewUrl}#${target.position}`).then(
      () => {
        if (generation !== this.generation) return
        if (!sameDeck) view.nudge()
        this.timer = setTimeout(
          () => {
            this.timer = null
            this.deckUrl = target.viewUrl
            this.live = true
            view.reveal()
            this.deps.onChange()
          },
          sameDeck ? HASH_FADE_MS : FADE_MS
        )
      },
      () => {

    this.view?.destroy()
    this.view = null
    this.deckUrl = null

// → projector mode, another display) by closing the old one and opening the new one at once, and
// the old window's 'closed' arrives after the new one opened, so it must not end the new one.
export function followProjectorWindow<W>(live: Pick<LiveSlide, 'close'>): {
  current(): W | null
  opened(window: W): void
  closed(window: W): void
} {
  let current: W | null = null
  return {
    current: () => current,
    opened: (window) => {
      live.close() // the view leaves any old window
      current = window
    },
    closed: (window) => {
      if (current !== window) return
      live.close()
      current = null
    }
  }
}

Create `src/main/canva/connection-watcher.ts`:

```ts
const POLL_MS = 15_000

// Notices the internet connection coming back (Electron's main process has no "online" event), so
// slides linked while offline get their images (spec §8.3). It polls `isOnline` every 15 s and calls
// `onReconnect` on each change from offline to online.
export class ConnectionWatcher {
  private online = true
  private timer: ReturnType<typeof setInterval> | null = null

  constructor(private readonly deps: { isOnline(): boolean; onReconnect(): void }) {}

  start(): void {
    this.online = this.deps.isOnline()
    this.timer = setInterval(() => {
      const online = this.deps.isOnline()
      if (online && !this.online) this.deps.onReconnect()
      this.online = online
    }, POLL_MS)
  }

  stop(): void {
    if (this.timer) clearInterval(this.timer)
    this.timer = null
  }
}
```

import { useEffect, useState } from 'react'

// Whether the Mac has an internet connection, following the browser's online and offline events.
export function useOnline(): boolean {
  const [online, setOnline] = useState(() => navigator.onLine)
  useEffect(() => {
    const update = (): void => setOnline(navigator.onLine)
    window.addEventListener('online', update)
    window.addEventListener('offline', update)
    return () => {
      window.removeEventListener('online', update)
      window.removeEventListener('offline', update)
    }
  }, [])
  return online
}

import { createContext, useCallback, useContext } from 'react'
import { useLibraryStore } from './library/LibraryProvider'

const EditSong = createContext<(songId: number) => void>(() => undefined)

// "Edit details" from any song menu: opens the Music page with the song selected and scrolled
// into view, so its editor shows. App switches the page; the library store selects the song.
export function EditSongProvider(props: {
  onShowMusic: () => void
  children: React.ReactNode
}): React.JSX.Element {
  const store = useLibraryStore()
  const { onShowMusic } = props
  const editSong = useCallback(
    (songId: number) => {
      onShowMusic()
      void store.getState().reveal(songId)
    },
    [store, onShowMusic]
  )
  return <EditSong.Provider value={editSong}>{props.children}</EditSong.Provider>
}
