# Folk Dance Player — Plan 8: Continuous Integration and Releases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub checks every pull request and makes releases. Specifically:
- **The PR Gate:** every pull request (and every push to main) must typecheck, pass the formatting check and the tests, build, and pass the end-to-end tests. A change to the app must add a CHANGELOG line. Branch protection requires all of it before a merge.
- **A release is two clicks:**
  1. **Prepare Release** opens a pull request that bumps the version and dates the CHANGELOG notes.
  2. **Create Release**, run after merging that PR, refuses a version that isn't new, then builds, checks and publishes the `.dmg` as a GitHub release.
- **Dependabot keeps dependencies current,** offering only releases at least 14 days old.

**Architecture:**
- **`scripts/release.mts`** holds the release rules as pure, unit-tested functions: comparing versions, the next version, moving the CHANGELOG's Unreleased notes, and checking a release. It also has two commands, `prepare` and `check`, that the workflows run. Node 24 runs the TypeScript file directly.
- **Four files in `.github/`:**
  - `workflows/pr-gate.yml`
  - `workflows/prepare-release.yml`
  - `workflows/create-release.yml`: check, a build matrix per OS, then one publish
  - `dependabot.yml`
- **Pinned and least-privilege:** actions are pinned to commit SHAs, and every workflow asks only for the permissions it needs.

**Decisions made with the user while planning** (in spec §13.4):
- **Create Release is manual and runs only on main.** It rejects a version that isn't higher than the last release, or has no CHANGELOG section.
- **The repo is public,** so hosted runners are free. The PR Gate checks on Linux and runs the end-to-end tests on macOS, as a matrix that Linux and Windows can join.
- **Extras:** Dependabot with a 14-day cooldown, branch protection, Prepare Release, and the CHANGELOG check.
- **Expandable to Windows:** Create Release is one workflow of jobs (check, then a build matrix, then a single publish), not one workflow per OS. A release is published once, with every installer, only after every build passes.
- **Publishing uses the workflow's own token;** no personal access token is needed.

## Review Focus

These are the five failure modes most likely to bite. Each has a test or a check in the task that owns it.

1. **A release that should have been refused is published:** an old or equal version, missing notes, or a run on another branch. Task 1: "a version that isn't higher…", "a version with no CHANGELOG section…"; Task 3: the "Releases come from main" step and `DRY_RUN`.
2. **A half-published release** (one OS built, another failed). Task 3: Publish `needs: [check, build]`, with `fail-fast: true` in the build matrix.
3. **The release PR can't be merged** because its checks never ran. Task 3 starts the PR Gate from Prepare Release; Task 5 checks that branch protection accepts it.
4. **The CHANGELOG check blocks harmless PRs** (Dependabot, docs, workflows). It applies only to `src/`, and skips Dependabot and the `no changelog` label (Task 2; verified both ways while planning).
5. **A fork's PR gets write access or secrets.** Task 2: `pull_request` only, `contents: read`, and event values through `env:` only.

```ts
// Release helpers for the Prepare Release and Create Release workflows (spec §13.4). Run with
// Node 24, which runs TypeScript directly:
//   node scripts/release.mts prepare <major|minor|patch|x.y.z>   bump the version, date the notes
//   node scripts/release.mts check [notes-file]                  may this version be released?
// The pure functions below are unit-tested; the commands at the bottom wire them to the files.
import { execFileSync } from 'node:child_process'
import { appendFileSync, readFileSync, writeFileSync } from 'node:fs'
import { pathToFileURL } from 'node:url'

const VERSION = /^(\d+)\.(\d+)\.(\d+)$/

function parse(version: string): number[] {
  const match = VERSION.exec(version)
  if (!match) throw new Error(`Not a version: ${version}`)
  return match.slice(1).map(Number)
}

export function compareVersions(a: string, b: string): number {
  const [x, y] = [parse(a), parse(b)]
  for (let i = 0; i < 3; i++) if (x[i] !== y[i]) return x[i] - y[i]
  return 0
}

export function nextVersion(current: string, bump: string): string {
  const [major, minor, patch] = parse(current)
  if (bump === 'major') return `${major + 1}.0.0`
  if (bump === 'minor') return `${major}.${minor + 1}.0`
  if (bump === 'patch') return `${major}.${minor}.${patch + 1}`
  parse(bump)
  return bump
}

const UNRELEASED = '## [Unreleased]'

// Keep a Changelog: the notes under Unreleased become the new version's section, dated, and
// Unreleased starts again, empty.
export function prepareChangelog(changelog: string, version: string, date: string): string {
  const start = changelog.indexOf(UNRELEASED)
  if (start < 0) throw new Error('The CHANGELOG has no "## [Unreleased]" section')
  const bodyStart = start + UNRELEASED.length
  const next = changelog.indexOf('\n## ', bodyStart)
  const body = changelog.slice(bodyStart, next < 0 ? undefined : next)
  if (!body.trim()) throw new Error('The CHANGELOG has nothing under Unreleased to release')
  return `${changelog.slice(0, bodyStart)}\n\n## [${version}] - ${date}${changelog.slice(bodyStart)}`
}

// The notes of one released version: its section's body.
function section(changelog: string, version: string): string | null {
  const heading = new RegExp(`^## \\[${version.replace(/\./g, '\\.')}\\].*$`, 'm').exec(changelog)
  if (!heading) return null
  const bodyStart = heading.index + heading[0].length
  const next = changelog.indexOf('\n## ', bodyStart)
  return changelog.slice(bodyStart, next < 0 ? undefined : next).trim()
}

export type ReleaseCheck = { ok: true; notes: string } | { ok: false; error: string }

// Create Release refuses a version that isn't higher than every released one (tags vX.Y.Z), or
// that has no notes in the CHANGELOG.
export function checkRelease(input: {
  version: string
  tags: string[]
  changelog: string
}): ReleaseCheck {
  const { version, tags, changelog } = input
  parse(version)
  const released = tags
    .map((t) => t.replace(/^v/, ''))
    .filter((t) => VERSION.test(t))
    .sort(compareVersions)
  const latest = released.at(-1)
  if (latest && compareVersions(version, latest) <= 0) {
    return {
      ok: false,
      error: `Version ${version} isn’t higher than the latest release, v${latest}. Bump it first (Prepare Release).`
    }
  }
  const notes = section(changelog, version)
  if (notes === null) {
    return {
      ok: false,
      error: `The CHANGELOG has no "## [${version}]" section. Run Prepare Release first.`
    }
  }
  if (!notes) return { ok: false, error: `The CHANGELOG's ${version} section is empty.` }
  return { ok: true, notes }
}

// --- Commands ------------------------------------------------------------------------------

const readVersion = (): string =>
  (JSON.parse(readFileSync('package.json', 'utf8')) as { version: string }).version

// Hands a value to the next workflow steps (and prints it for people).
function output(name: string, value: string): void {
  console.log(`${name}=${value}`)
  if (process.env['GITHUB_OUTPUT'])
    appendFileSync(process.env['GITHUB_OUTPUT'], `${name}=${value}\n`)
}

function main(args: string[]): void {
  const [command, arg] = args
  if (command === 'prepare') {
    const current = readVersion()
    const version = nextVersion(current, arg ?? '')
    // The current version is allowed too: the first release has nothing to bump.
    if (version !== current) {
      execFileSync('npm', ['version', version, '--no-git-tag-version'], { stdio: 'inherit' })
    }
    const today = new Date().toISOString().slice(0, 10)
    writeFileSync(
      'CHANGELOG.md',
      prepareChangelog(readFileSync('CHANGELOG.md', 'utf8'), version, today)
    )
    output('version', version)
  } else if (command === 'check') {
    const version = readVersion()
    const tags = execFileSync('git', ['tag', '--list', 'v*'], { encoding: 'utf8' }).split('\n')
    const result = checkRelease({ version, tags, changelog: readFileSync('CHANGELOG.md', 'utf8') })
    if (!result.ok) {
      console.error(`::error::${result.error}`)
      process.exit(1)
    }
    if (arg) writeFileSync(arg, `${result.notes}\n`)
    output('version', version)
  } else {
    console.error(
      'Usage: node scripts/release.mts prepare <major|minor|patch|x.y.z> | check [notes-file]'
    )
    process.exit(2)
  }
}

if (import.meta.url === pathToFileURL(process.argv[1] ?? '').href) main(process.argv.slice(2))
```

```yaml
# PR Gate (spec §13.4): every pull request, and every push to main, must typecheck, pass the
# formatting check and the tests, build, and pass the end-to-end tests. Pull requests that change
# the app must also add a CHANGELOG line. Branch protection requires these checks before merging.
name: PR Gate

on:
  pull_request:
    types: [opened, synchronize, reopened, labeled, unlabeled]
  push:
    branches: [main]
  # Prepare Release starts this on its release branch: a PR opened by a workflow doesn't start
  # other workflows by itself, and branch protection needs these checks to merge it.
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: pr-gate-${{ github.ref }}
  cancel-in-progress: true

jobs:
  check:
    name: Typecheck, test and build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm install --global npm@12.1.0
      - run: npm ci
      - run: npx prettier --check .
      - run: npm run typecheck
      - run: npm test
      - run: npx electron-vite build

  e2e:
    name: End-to-end (${{ matrix.os }})
    strategy:
      fail-fast: false
      matrix:
        # macOS first; ubuntu-latest (under a virtual display) and windows-latest can join later.
        os: [macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm install --global npm@12.1.0
      - run: npm ci
      - run: npm run test:e2e
      - name: Keep Playwright's report of a failure
        if: failure()
        uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
        with:
          name: e2e-results-${{ matrix.os }}
          path: test-results/
          retention-days: 7

  changelog:
    name: CHANGELOG
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 2 # the PR's merge commit and its first parent, today's main
      - name: A change to the app adds a CHANGELOG line
        env:
          AUTHOR: ${{ github.event.pull_request.user.login }}
          LABELS: ${{ toJSON(github.event.pull_request.labels.*.name) }}
        run: |
          if [ "$AUTHOR" = "dependabot[bot]" ] || echo "$LABELS" | grep -q '"no changelog"'; then
            echo "No CHANGELOG line needed (Dependabot, or labeled 'no changelog')."
            exit 0
          fi
          # The merge commit against today's main: exactly this PR's changes. (The event's base SHA
          # goes stale when main moves, and would count other PRs' files.)
          changed=$(git diff --name-only HEAD^1 HEAD)
          if echo "$changed" | grep -q '^src/' && ! echo "$changed" | grep -qx 'CHANGELOG.md'; then
            echo "::error::This PR changes the app (src/) but not CHANGELOG.md. Add a line under Unreleased, written for organizers, or label the PR 'no changelog' if nobody would notice the change."
            exit 1
          fi
          echo "OK"
```

Create `.github/workflows/prepare-release.yml`:

```yaml
# Prepare Release (spec §13.4): run from the Actions tab on main. It bumps the version, moves the
# CHANGELOG's Unreleased notes under it, and opens a pull request "Release vX.Y.Z". Merge it, then
# run Create Release.
name: Prepare Release

on:
  workflow_dispatch:
    inputs:
      bump:
        description: 'major, minor, patch, or an exact version such as 1.0.0 (the first release: 0.1.0)'
        required: true

permissions:
  contents: write
  pull-requests: write
  actions: write

jobs:
  prepare:
    runs-on: ubuntu-latest
    steps:
      - name: Releases are prepared from main
        if: github.ref != 'refs/heads/main'
        run: |
          echo "::error::Run Prepare Release on main (pick main under 'Use workflow from')."
          exit 1
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
      - id: bump
        env:
          BUMP: ${{ inputs.bump }}
        run: node scripts/release.mts prepare "$BUMP"
      - name: Open the release pull request
        env:
          GH_TOKEN: ${{ github.token }}
          VERSION: ${{ steps.bump.outputs.version }}
        run: |
          branch="release/v$VERSION"
          git config user.name 'github-actions[bot]'
          git config user.email '41898282+github-actions[bot]@users.noreply.github.com'
          git switch -c "$branch"
          git commit -am "chore(release): v$VERSION"
          git push origin "$branch"
          gh pr create --base main --head "$branch" --title "Release v$VERSION" \
            --body "Bumps the version to $VERSION and dates its CHANGELOG notes. When this is merged, run **Create Release** on main."
          # A PR opened with this workflow's token doesn't start the PR Gate; start it here.
          gh workflow run pr-gate.yml --ref "$branch"
```

Create `.github/workflows/create-release.yml`:

```yaml
# Create Release (spec §13.4): run from the Actions tab on main.
# 1. Check: the version must be higher than the last release and have CHANGELOG notes.
# 2. Build, one job per OS (a matrix, like the PR Gate's end-to-end tests): test, build the
#    installer, check it with the end-to-end tests, keep it as an artifact.
# 3. Publish, once every build has passed: tag vX.Y.Z and publish one GitHub release with every
#    installer and the CHANGELOG notes, so a release is never half-published.
# A dry run (any branch) does everything but publish, and keeps the installers for a week.
name: Create Release

on:
  workflow_dispatch:
    inputs:
      dry_run:
        description: 'Dry run: build and check only; publish nothing'
        type: boolean
        default: false

permissions:
  contents: read

concurrency:
  group: create-release
  cancel-in-progress: false

env:
  # Anything but a manual run with "dry run" unchecked publishes nothing.
  DRY_RUN: ${{ github.event_name != 'workflow_dispatch' || inputs.dry_run }}

jobs:
  check:
    name: Check the version
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.version.outputs.version }}
    steps:
      - name: Releases come from main
        if: env.DRY_RUN != 'true' && github.ref != 'refs/heads/main'
        run: |
          echo "::error::Run Create Release on main (pick main under 'Use workflow from'). A dry run may use any branch."
          exit 1
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0 # the tags, to compare versions
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
      - id: version
        run: echo "version=$(node -p 'require("./package.json").version')" >> "$GITHUB_OUTPUT"
      - name: The version is new and has release notes
        # A dry run reports a failed check but goes on, to test the builds.
        continue-on-error: ${{ env.DRY_RUN == 'true' }}
        run: node scripts/release.mts check

  build:
    name: Build (${{ matrix.os }})
    needs: check
    strategy:
      fail-fast: true
      matrix:
        include:
          # Each OS builds its own installer. Windows joins with its electron-builder target, e.g.
          # { os: windows-latest, installer: 'dist/*.exe' }.
          - os: macos-latest
            installer: 'dist/*.dmg'
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm install --global npm@12.1.0
      - run: npm ci
      - run: npm test
      - run: npm run dist
      - run: npm run test:e2e:dist
      - uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
        with:
          name: installer-${{ matrix.os }}
          path: ${{ matrix.installer }}
          retention-days: 7
          if-no-files-found: error

  publish:
    name: Publish
    needs: [check, build]
    runs-on: ubuntu-latest
    permissions:
      contents: write # the tag and the release
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version-file: .nvmrc
      - name: Release notes
        continue-on-error: ${{ env.DRY_RUN == 'true' }}
        run: node scripts/release.mts check release-notes.md
      - uses: actions/download-artifact@3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c # v8.0.1
        with:
          pattern: installer-*
          path: installers
          merge-multiple: true
      - run: ls -la installers
      - name: Publish the release
        if: env.DRY_RUN != 'true'
        env:
          GH_TOKEN: ${{ github.token }}
          VERSION: ${{ needs.check.outputs.version }}
        run: |
          gh release create "v$VERSION" installers/* --target "$GITHUB_SHA" \
            --title "Folk Dance Player $VERSION" --notes-file release-notes.md
```

## Changes after execution

The final review found nothing Critical. I fixed the two Important findings, and two Minor ones that I re-graded to Important for their effect on a maintainer:

- **Task 5 Step 3 now proves the dispatch path.** The throwaway PR's commit has `[skip ci]`, so only the dispatched PR Gate run can satisfy the required checks, as for a release PR that a workflow opens. Before, the PR's own `pull_request` run made it pass either way.
- **Branch protection is the repo's existing `main` ruleset.** It already requires pull requests (squash merges) and blocks force-pushes and deletion, with no bypass. Task 5 Step 2 adds a required-status-checks rule to it, with the checks required to come from GitHub Actions, instead of a second, classic protection layer. The spec's "admins can still push in an emergency" was wrong, and is gone.
- **The CHANGELOG check compares the PR's merge commit with its first parent** (`git diff HEAD^1 HEAD`). The event's base SHA goes stale when main moves, and would count other PRs' files.
- **Prepare Release has no default bump.** With the old default, `minor`, a first run would have released v0.2.0. The first release is `0.1.0`, as the input's description, CONTRIBUTING and the spec say.

**Deferred minors from the final review:**
- Any label change re-runs the whole gate. On main, back-to-back merges can cancel each other's PR Gate runs (`cancel-in-progress`).
- `prepare` accepts an exact version lower than the current one.
- Prepare Release runs `npm version` with Node's bundled npm, not 12.1.0.
- If an asset upload fails, re-running Publish can leave a second draft release (nothing is published or tagged).
- An Unreleased section with headings but no bullets counts as having notes.
- Re-running Prepare Release while an earlier `release/vX` branch exists fails late, with git's error.
