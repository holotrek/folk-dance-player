# AGENTS.md

Guide for AI agents (and people) working on Folk Dance Player. Read this first.

## Orientation

Folk Dance Player is a macOS-first Electron app for folk dance organizers: index a music library,
build a **program** (the dances for one session), play it, and show a large-font **projector view**
with Canva slides on a second display. It replaces an earlier Flutter app and is inspired by
MITPlayer.

- Spec: `docs/superpowers/specs/2026-10-13-folk-dance-player-electron-design.md`
- Plans: `docs/superpowers/plans/` (one per subsystem; written when reached)
- Release notes: `CHANGELOG.md` · How to contribute: `CONTRIBUTING.md`

## Non-negotiable conventions

- **The main process owns all state.** Renderers call `window.api.invoke` on channels in `src/shared/contract.ts`. The projector window is read-only.
- **Use `node:sqlite`.** Schema changes are new numbered migrations. A migration that has been released is never edited.
- **Keep the data layers separate.** `files` holds local facts, `songs` holds shareable facts (one per file), and `file_prefs`, `playlists` and `slide_cache` hold personal or local data.
- **UI comes from Mantine components.** Custom CSS goes only in co-located `*.module.css` files.
- **Pin exact dependency versions,** each at least two weeks old when added.
- **Work test-first** (Vitest). Commit with conventional-commit messages.
- **Add a `CHANGELOG.md` line** under `Unreleased` for every user-facing change, in the same commit.
- **Add a decision below** whenever you make one a future contributor would otherwise have to rediscover.

## Decisions

Newest first. Format: **date — decision.** Why. _Rejected:_ alternatives.

- **2026-10-15 — The pre-release hardware checklist lives in `docs/manual-testing/pre-release-hardware.md`, and Prepare Release copies it into the release pull request's description.** GitHub makes task-list checkboxes clickable only in issues, pull requests and comments, not in a rendered file. In the draft release PR they're ticked while testing, before Ready for review, and each release keeps its record. _Rejected:_ ticking the file itself (not clickable); an issue per release from a template (separate from the release flow, easy to forget).
- **2026-10-15 — Create Release is one workflow: check, a build matrix (one job per OS), then a single publish.** One version check for every OS, and a release that is all or nothing: Publish runs only after every build passes, and creates the tag and release once, with every installer. Windows joins as a matrix entry. _Rejected:_ one release workflow per OS (they'd race to create the same tag and could publish half a release).
- **2026-10-15 — Prepare Release opens a draft PR; the maintainer's "Ready for review" starts the PR Gate.** A pull request opened with a workflow's `GITHUB_TOKEN` starts no workflows. Tested: a dispatched PR Gate run (`gh workflow run pr-gate.yml --ref <branch>`) puts passing checks on the head commit, but they don't count toward the ruleset's required checks; the PR stays BLOCKED. Marking the draft ready is a person's action, so `ready_for_review` runs the gate. _Rejected:_ dispatching the gate (doesn't satisfy required checks); a personal access token or GitHub App (a secret to create and renew).
- **2026-10-15 — Dependabot ignores major npm upgrades.** Its first run proposed Vite 8 (electron-vite 5 supports only Vite 7), `@types/node` 26 (the app runs Node 24), and TypeScript 7 and Vitest 5 (migrations). Majors are deliberate upgrades; patch and minor updates keep coming.
- **2026-10-15 — `npm run dist` passes `--publish never`.** On CI, electron-builder publishes by itself ("Implicit publishing triggered by CI detection") and fails without a token. Publishing is Create Release's Publish job, with the workflow's own token, so no personal access token is needed.
- **2026-10-15 — Actions are pinned to commit SHAs (the version in a comment), and Dependabot waits 14 days (`cooldown`).** The same two-week rule as npm packages; SHAs can't be moved under us like tags. Release rules live in `scripts/release.mts` (unit-tested), which Node 24 runs directly.
- **2026-10-14 — The `.dmg` is ad-hoc signed (`identity: '-'`, no hardened runtime) until there's an Apple Developer ID.** Apple silicon refuses unsigned code, and a consistent signature makes a downloaded copy "from an unidentified developer" (Open Anyway) instead of "damaged". It is Universal (one `.dmg`, ~230 MB). CONTRIBUTING.md has the untested signing and notarizing steps. _Rejected:_ no signature (broken on Apple silicon once the bundle is modified); Apple-silicon-only (Intel Macs are still common).
- **2026-10-14 — The startup backup uses `VACUUM INTO` before migrations, and logging never throws.** `VACUUM INTO` makes a consistent copy of an open WAL database; taking it before `migrate` keeps a copy of the old schema if a migration goes wrong. A failed backup is logged and startup goes on, and the logger swallows its own errors (spec §10.1: side failures never stop the music). `FDP_USER_DATA` also moves the log, so test runs never write to `~/Library/Logs`.
- **2026-10-14 — End-to-end tests launch `electron .`, drag in steps, and can target the packaged app.** Launched as `electron out/main/index.js`, the app has no `package.json` beside it and reports Electron's version. `Locator.dragTo` sends one or two `dragover`s and lost about 1 drop in 8–16 when one landed during a re-render; `drag()` in `e2e/app.ts` moves in ten steps. Playwright matches names partially ("Play" is in "New playlist"), so use `exact: true`. `FDP_APP` (`npm run test:e2e:dist`) runs the same tests on the packaged `.app`.
- **2026-10-14 — Small UI rules from the post-Plan 6 tweaks.**
  - **Auto-show (laptop mode's `autoFullscreen.*`) is edited only in the player bar,** beside the Projector switch, like auto-continue. The bar reads settings once, so a second editor in Settings would leave it stale.
  - **Choosing the dance when adding:** `programs:addTracks` still adds each song as its default dance; the renderer then reads the program, and for new items with `danceCount > 1` opens "Which dance?" and applies changes with `programs:setItemDance`. Main stays unchanged and every add path (drag, ➕) gets it.
  - **Playlist numbers come from main** (`LibraryRow.playlistNumber`, counted from `playlist_items.position`), because the visible order changes with sort and search.
  - **`<FavoriteToggle>`** is the one favorite star (library rows, holding, program items); its hover-only styling keys off `[role=row]`/`[role=listitem]`, so it works in any list.
  - **`<SearchInput>`** is the one search box (✕ to clear, Chromium's own cancel button hidden).
  - **Appearance** is the `appearance` setting, applied with Mantine's `setColorScheme` at startup (`useAppearance`) and on change; Mantine's own localStorage copy only avoids a flash.
- **2026-10-14 — The logo is one all-black SVG (`src/renderer/src/assets/logo.svg`), drawn by `<Logo>` as a CSS mask filled with the current text color (or a `color`).** It follows the theme and the projector's gray with no recolored copies. The app icon is that logo in white on the app's red tile (`build/icon/icon.html`); `npm run icon` renders it with Electron and writes `build/icon.png`, `build/icon.icns` (for electron-builder) and `resources/icon.png` (the Dock icon when unpackaged). _Rejected:_ an inline React SVG (54 KB of paths in a component); recolored SVG copies per theme.
- **2026-10-14 — Canva runs in its own sandboxed session; the app's windows are sandboxed too, and only one copy of the app runs.** The live view and the capture window use the `persist:canva` session with no preload, muted, and `guardCanva` lets them navigate (and be redirected) only within `https://*.canva.com` and never open windows. A load counts only if it ends on the deck's own view page with HTTP 200 (`isDeckView`), so a Wi-Fi login page or Canva's sign-in page is never shown or captured; a redirected deck fetch is "unreachable", and only decks read fine are re-captured. Both app windows now use `sandbox: true` (the preloads need only `electron`; check with `grep -o 'require("[^"]*")' out/preload/*.js`), replacing the 2026-10-13 "`sandbox: false` for now". `requestSingleInstanceLock()` keeps a second copy from opening the same library; a second launch focuses the control window.
- **2026-10-14 — The projector shows a dance's saved slide image at once and the live Canva view only once its controls have faded** (`LiveSlide`: 11 s after a new deck loads and gets its mouse pass, 1.5 s after another slide of the loaded deck). Chosen by the user. Canva fades its controls only about 10 s after mouse activity, and the projector must never show them, a blank page or "Loading…". Only a slide of a deck whose controls have faded changes in place (1.5 s, no mouse pass, which would bring them back); a switch before the fade starts over. Offline, or after a failed load, the image stays. The projector window ignores the mouse (`setIgnoreMouseEvents`), so the operator's cursor can't wake the controls; laptop mode still closes on mouse movement because `ActivityWatcher` polls the cursor. `followProjectorWindow` keeps the live view on a replacement window: the controller closes and reopens synchronously, and the old window's `closed` arrives later. `slideBox()` (in `shared/projector.ts`) is used by both the projector page and main, so the live view covers the image exactly. _Rejected:_ live first with the image only offline (controls visible for ~10 s on every change).
- **2026-10-14 — Canva in main is pure modules over injected pieces:** `canva-url` and `deck-parser` (the public view page), `decks` (the repository), `CanvaService` (add, link, refresh, startup) over a `Fetcher`, `CaptureQueue` over a `SlideCapturer` (`createSlideCapturer` drives one off-screen `CanvaPage`, reused within a deck), and `LiveSlide` over a `LiveView`. Only `electron-canva.ts` touches Electron. A dance stores its slide's page ID; its position is always looked up from the deck's current slide list, so moving slides in Canva never breaks a link, and a slide gone from its deck keeps its image but is never shown live. Captures at startup (when online) cover only linked slides without an image; "Refresh slides" re-captures all. A finished capture batch keeps its counts, so the control window can say how many failed. The test fixture `tests/fixtures/canva-view.html` keeps Canva's minified format and is in `.prettierignore`.
- **2026-10-14 — `PlayerSession` decides what plays; the control window only plays and reports.**
  - **How it works:** the session reaches the database through `SessionPorts` and gets its timers injected, so tests run it over an in-memory database with fake timers. The control window's `<audio>` follows the broadcast `player:state` and reports only `player:ended` and `player:failed`, each with the play's `playId`; a late event from an earlier song is ignored.
  - **STOP markers:** operator commands (▶, ⏭) pass them, marking them played; only automatic continuation halts at one (chosen by the user).
  - **Missing files:** a song whose file is missing is skipped and left unplayed and flagged, so the cursor (the first unplayed item) never gets stuck on it.
  - **Settings:** speed lock and volume live in the session, not settings.
  - _Rejected:_ the renderer deciding the next song (the Flutter app's desync bugs).
- **2026-10-14 — Audio is served by `fdp-media://file/<id>`, with Range handled in `mediaResponse`.** The renderer runs on a dev-server origin, where `file://` media is blocked. Serving by file id means a page can't ask for arbitrary paths. Seeking needs 206 responses, and we answer Range requests ourselves rather than rely on `net.fetch` of a `file://` URL. The CSP allows `media-src fdp-media:`.
- **2026-10-14 — `FDP_USER_DATA` points the app at another data folder.** `--user-data-dir` doesn't move `app.getPath('userData')`. Use the variable for smoke runs and end-to-end tests, so they never touch a real library.
- **2026-10-14 — Drag and drop is native HTML5 with the app's own MIME types** (`FILES_MIME` for songs, `ITEMS_MIME` for program items in `library/drag.ts`). It covers every drag in the app (library to playlists, holding and programs; reordering playlists and programs). _Rejected:_ dnd-kit, as the spec first planned (not needed, and native events also work for drops between panels).
- **2026-10-14 — The Program page has its own store (`createProgramStore`, `ProgramProvider`) beside the library store.** It holds the program list, the loaded program, its play log and the player state. It refetches on `programs:changed` and `library:changed` (labels can change), and takes every `player:state`; the first `player:getState` answer is ignored if a broadcast already arrived (it would be older). The library list, its search and its selection stay in the library store, shared by both pages. Main coalesces the many change notices of one action (a song start marks an item played and writes the log) into one broadcast.
- **2026-10-14 — ⏹ keeps the song loaded ("stopped", rewound to the start); ▶ plays it again as the same play.** Chosen by the user: stopping to re-teach a figure and pressing ▶ must neither skip the dance nor add a second Previously played entry. A preview or replay that interrupts a program song puts it back as next up instead (its `played_at` is cleared; its `play_log` row stays), since something else is now loaded. ⏭ means "skip", so the song stays played. _Rejected:_ ⏹ putting the song back into the program (each ⏹/▶ added a log entry); marking an item played only when it ends (the projector and the log need the start).
- **2026-10-14 — The projector window is managed by `ProjectorController` (display choice, projector vs laptop mode, display events) and fed by `createProjectorFeed`; `ActivityWatcher` handles laptop mode's mouse/Esc dismissal and the idle auto-fullscreen.** All three take injected Electron pieces, so they're unit-tested. Rules learned on real hardware: call `setVisibleOnAllWorkspaces` with `skipTransformProcessType` (otherwise macOS can leave the app as a background app after sleep: no Dock icon, no ⌘-Tab, control window hidden); after any display change keep the control window off the projector's display; on wake re-check displays and show the control window; at startup reopen projector mode only with a projector connected; block display sleep while the view shows or music plays. From the final review: the control window is also moved back when the operator drags it onto the projector (`moved`); projector mode closes rather than cover the operator's only display; idle time also uses `powerMonitor.getSystemIdleTime()` (scrolling and clicks don't move the cursor); `NowPlaying.logId` keeps the playing song out of the projector's previously played; `atStop` holds only while the halted program's next item is unchanged. Known issue: unplugging mid-session can orphan the projector window (`docs/spikes/projector-unplug.md`). The projector page has its own read-only preload.
- **2026-10-14 — The remote's media keys are Electron global shortcuts in the main process (`remote/media-keys.ts`), and Chromium's media-key handling is off.** A spike (`docs/spikes/remote-control.md`) showed media keys never arrive as key events, and macOS sends them to the "Now Playing" app, which the app isn't when idle (the user's remote opened QuickTime), so Media Session handlers can't start a program. Chromium's default handling also paused `<audio>` directly, behind `PlayerSession`. Global shortcuts worked idle or playing, focused or not. Play/pause → `toggle()`, next → `next()`, back → `restart()` (◀◀ now goes through main too: `NowPlaying.restarts`), stop → `stop()`. macOS requires Accessibility trust; Settings shows `remote:status` and `remote:requestAccess` prompts. _Rejected:_ `navigator.mediaSession` handlers (need the app to be Now Playing).
- **2026-10-14 — Migration 003 adds `file_prefs.holding_position`, so Holding keeps the order songs were placed in.** The user wanted Holding's drag and drop to match the program's (slot in between songs, or at the end). `setHolding(fileIds, true, beforeFileId)` places songs, and moves songs already held, which is how the panel reorders; releasing clears the position. Songs held before the migration are numbered in title order. The holding filter of `listLibrary` always sorts by position.
- **2026-10-14 — Icons are inline SVG components (`components/icons.tsx`), never Unicode symbols.** ⏸ and ⏹ (and others) render as colored emoji on macOS while ▶ doesn't, so buttons and STOP rows looked mismatched.
- **2026-10-14 — The player bar is mounted once, above the page tabs (in `App`'s header).** The user wanted to control a preview started on the Music page without switching pages, and the `<audio>` element lives in the player bar, so on the Program page alone it was unmounted (cutting the music) on every page change. The header's height follows the bar (`useElementSize`) so a warning line doesn't overlap the page. _Rejected:_ the player bar on the Program page only.
- **2026-10-14 — The sidebar is one component per section** (`components/sidebar/`: `LibrarySection`, `PlaylistsSection`, `ProgramsSection`, plus `DropTarget`, `FilterEntry` and `SectionHeading`). `Sidebar.tsx` only composes them, so each section can grow without the file becoming unwieldy.
- **2026-10-14 — Re-apply mapping asks for the mapping each time, beside the selected songs' tags; the Apple Music import shows a random sample of 50 tracks' tags.** Seeing the tags is what tells an organizer which tag holds teachers or choreographers. The Re-apply choice starts from the import settings and is not saved (`library:reapplyMapping` takes the mapping; `library:songTags` reads tags). The Apple sample comes from `Library.xml`, which is already parsed for the preview, so it costs nothing extra; file imports get no preview, because tags are read only after the mapping is chosen. Both use `TagPreviewTable`. _Rejected:_ re-applying with the saved settings only (the user had to change Settings first, blind).
- **2026-10-14 — A merge never loses personal data.** Notes are added together, "Different dance" answers move to the kept dance (the `ON DELETE CASCADE` on `distinct_dances` would otherwise drop them), and only difficulty and the slide keep the kept dance's value. "Same dance" stays one click with no confirmation. Same-name suggestions skip dances no song uses.
- **2026-10-14 — Don't center a Mantine button with `transform`.** Mantine's pressed state sets its own `transform` on buttons and action icons, which replaces a centering `translateY(-50%)` and makes the button jump. Use `top: 0; bottom: 0; margin-block: auto` instead.
- **2026-10-13 — Library UI state lives in a Zustand store created per API (`createLibraryStore`), provided by `LibraryProvider`.** The sidebar, table and editor share the filter, search, sort, rows and selection. Main stays the source of truth: every library or playlist edit returns, then main broadcasts `library:changed` (also after each import), and the store and editor refetch. `watch()` subscribes from an effect, so StrictMode's double mount doesn't drop the listener. Zustand selectors must return stable values; use `store.getState().selectedRows()` in handlers, never inside a selector.
- **2026-10-13 — The Music page table is browse-only; all editing is in the side editor.** Chosen by the user: it keeps the virtualized table (`@tanstack/react-virtual`) fast with large libraries and puts autocomplete editing in one place. Fields save on blur, once per change. _Rejected:_ spreadsheet-style inline cells.
- **2026-10-13 — Migration 002 adds `distinct_dances` ("Different dance" answers).** This is the first migration after 001 was merged; from here on, schema changes are new migrations, because users may have real data.
- **2026-10-13 — Re-apply mapping overwrites only the fields the mapping targets, and skips a default dance shared with other songs.** This is consistent with the import rule that one song's tags never change a shared dance; the result reports the skipped count.
- **2026-10-13 — Renderer tests run in jsdom, which lacks layout and some browser APIs; the test setup fills the gaps.**
  - **Test theme:** Mantine menus and popovers get `hideDetached: false` (otherwise every dropdown is `display: none`).
  - **Size stubs:** elements report a non-zero `getBoundingClientRect` and `offsetWidth`/`offsetHeight`, so virtualized lists render rows.
  - **Other stubs:** `document.fonts` (for auto-growing textareas), plus `matchMedia`, `ResizeObserver` and `scrollIntoView` from Plan 1.
  - **Two quirks:** Mantine's Rating takes clicks on each star's _label_, and TagsInput labels two inputs, so find it by placeholder.
- **2026-10-13 — Imports run in a utility process (one per job), and the main process writes the results.** The worker scans folders, reads tags and fingerprints files. `ImportService` saves each file in its own transaction as results arrive, streams `import:progress` events, and runs one import at a time. `worker-core.ts` has no Electron imports, so tests run the real pipeline in-process against generated MP3s and Apple XML. A cancelled Apple import leaves playlists untouched, because they'd be incomplete. _Rejected:_ importing on the main process (blocks the UI on large libraries); worker threads (a crash in a parser would take down the main process).
- **2026-10-13 — `music-metadata` and `plist` are devDependencies, so Vite bundles them.** Both are ESM-only, and `plist` exports only an `import` condition. Left external, the utility process crashed with an ES-module resolution error; bundled, both work in the built app. Import `plist` as `import { parse } from 'plist'`.
- **2026-10-13 — Re-import matching order: same path, then Apple persistent ID, then fingerprint (only when the old copy is missing or gone).** A fingerprint match keeps the file row, so songs, prefs, playlists and history follow a moved file. A copy whose original still exists is a new file. Existing songs only get empty fields filled: on the song, on its default dance _only if no other song uses that dance_ (one tune's tags must never change a dance shared with others), and on that pairing's teacher. Nothing is filled through a fallback dance, and a dance the user unlinked is never recreated.
- **2026-10-13 — An edited Apple playlist defaults to "keep" on re-import.** "Keep both" turns the edited copy into a `local` playlist, and the Apple copy ("Name (Apple Music)") takes over the persistent ID.
- **2026-10-13 — Renderer error messages go through `errorMessage()`,** which strips Electron's "Error invoking remote method…" prefix before organizers see them.
- **2026-10-13 — Search folds letters the tokenizer can't, and search-box text always goes through `toFtsQuery()`.** The FTS5 `unicode61 remove_diacritics 2` tokenizer strips combining accents (ş, ç, é) but not separate letters (ı, ł, ø, æ, ß, đ, þ). So `library_fts` is a contentless index (`content = ''`, `contentless_delete = 1`) with one row per song: its title and artist, plus the name, country and choreographer of every linked dance and the pairings' teachers. Triggers on `songs`, `dances`, `dance_songs` and `dance_song_prefs` keep it current, and fold those letters using a frozen copy of `FOLD_MAP`. `toFtsQuery()` folds the query the same way and quotes each word as a prefix term, because raw text such as "4-Wall" makes `MATCH` throw. To change folding later, add a migration that rebuilds `library_fts`; a test checks that the migration's copy covers `FOLD_MAP`. _Rejected:_ a SQL function registered with `db.function()` (triggers would break on any connection without it); storing folded shadow columns in `songs` and `dances`.
- **2026-10-13 — Settings are stored as JSON per key and validated on both write and read.** An unknown key or invalid value is rejected on `set`. A stored value that is corrupt or the wrong type silently falls back to its default on `get`, so an old or hand-edited database never crashes the app.
- **2026-10-13 — The app refuses a library database with a newer `user_version`.** It shows a "created by a newer version" dialog and quits without migrating. Each migration and its `user_version` bump run in one transaction.
- **2026-10-13 — `postinstall` runs `install-electron`.** Electron 44 has no install script of its own, and electron-vite fails with "Electron uninstall" without the binary.
- **2026-10-13 — Windows use `sandbox: false` for now** (the electron-vite template default). The preload is CommonJS and only needs `electron`, so `sandbox: true` should work. Turn it on, along with a navigation guard and a single-instance lock, before Canva web content is loaded (plans 6 and 7).
- **2026-10-13 — Kept the spike's `display-mode.swift` at `docs/spikes/`.** It is the verified CoreGraphics helper (mirror → extended, laptop as main display) that the post-v1 display setup assistant needs.
- **2026-10-13 — Mantine components with scoped CSS Modules for the UI.** Avoid hand-rolling standard controls (autocomplete, number inputs, dialogs, notifications); keep custom CSS small and component-scoped. _Rejected:_ shadcn/ui + Tailwind (utility classes instead of scoped CSS), Radix Themes (no autocomplete or notifications).
- **2026-10-13 — Built-in `node:sqlite` instead of `better-sqlite3`.** No native add-on to rebuild for Electron, and tests run on the same SQLite (3.53.4, FTS5) as the app. _Rejected:_ better-sqlite3 (needs separate builds for Node and Electron).
- **2026-10-13 — Exact version pins, each at least two weeks old; Vite stays on 7.x.** Reproducible builds, and avoiding brand-new releases. electron-vite 5 supports Vite only up to 7.
- **2026-10-13 — Double-click plays a preview everywhere except the program.** A preview stops the current song, is logged and shown on the projector, and never auto-continues; afterwards the program's next item is queued. Double-clicking in the program does nothing, because the program means "play in this order"; drag an item to the top instead.
- **2026-10-13 — Played program items are hidden but kept** (`program_items.played_at`). Saved programs record what was actually danced. _Rejected:_ deleting items as they play (the Flutter behavior).
- **2026-10-13 — Auto-continue is on by default,** with the delay editable in the player bar. STOP markers, replays and previews always halt.
- **2026-10-13 — Playlists are separate from programs.** Playlists organize the library; programs are a session's running order. Apple Music playlists are recreated exactly, and a re-import asks before overwriting local edits.
- **2026-10-13 — Dances are separate from songs, many-to-many, with an automatic one-to-one dance per imported song.** One tune can carry several dances, and one dance (Lesnoto) works with many tunes. Dance names aren't unique: there are several Svornatos by different choreographers. Import gives each new song its own same-named dance, its default, and never links by name; the library suggests "same dance?" instead. Each file still has exactly one `songs` row, so editing one recording never affects another. The teacher lives on the dance–song pairing (`dance_song_prefs`), the default dance on `song_prefs`, and difficulty, notes and the Canva slide on `dance_prefs`; all of these are personal. Songs, dances and pairings are the shareable layer. Labels show `Song | Dance (Choreographer)`, dropping the song when it matches the dance name and the choreographer unless the song's dances have more than one. _Rejected:_ dance fields on `songs` (can't model one tune with several dances); several files sharing one song; linking by name on import (wrong for the Svornatos).
- **2026-10-13 — Canva slides use the plain `/view` link in a `WebContentsView`, with a synthetic mouse pass after every slide change; saved slide images are used when offline.** `/view` can't be iframed (X-Frame-Options: deny). `?embed` can, but its controls never fade. Canva fades its controls only after mouse activity. _Rejected:_ `?embed` iframe, and cropping (the controls overlap slide content).
- **2026-10-13 — The projector window is borderless** (`frame: false`, `enableLargerThanScreen: true`, `setAlwaysOnTop(true, 'screen-saver')` before `setBounds`, `showInactive()`). This was the most seamless option on laptop and projector. Without `enableLargerThanScreen`, macOS clamps the window below the menu bar. _Rejected:_ native macOS fullscreen (new Space and an animation), simple fullscreen.
- **2026-10-13 — The projector view never closes on mouse or Esc in projector mode;** it does in laptop mode. The operator keeps working while the projector is up. Laptop mode must always be escapable.
- **2026-10-13 — Main process is the single source of truth; the control window plays audio through `<audio>`.** This prevents the Flutter app's desync bugs. `<audio>` with `preservesPitch` gives speed changes without changing pitch (verified at 0.5×, 0.75× and 1.25×). _Rejected:_ state in the renderer synced with BroadcastChannel; audio in a hidden window.
- **2026-10-13 — Electron rewrite of the Flutter app, macOS first.** The Flutter version couldn't reliably put a fullscreen window on a second display; a spike proved Electron can. _Rejected:_ continuing with Flutter.
